# ARTLINE Rich Studio: правила для Claude

## Кожна зміна йде через PR

Правило власника від 2026-10-26: у цьому репозиторії зміни потрапляють у `main` тільки через PR. Воно діє для всіх сесій і агентів і переважає загальне «не комітити й не пушити самому». Злиття робить власник.

1. Гілка від свіжого `origin/main`: `feat/…`, `fix/…`, `chore/…`, одна задача на гілку. У `main` напряму не комітити.
2. **Не будувати PR поверх гілки іншого PR.** `gh pr merge --delete-branch` видаляє базову гілку, і GitHub закриває залежний PR замість того, щоб перевести його на `main`: так втратився PR #4. Якщо дві зміни піднімають версію, наступну гілку робити від `main` після злиття першої.
3. У коміт додавати лише файли цієї зміни. Чужі незакомічені файли (`docs/riches/`, `docs/audits/artline-*`) не чіпати.
4. **Перед PR:**
   - запустити pytest (`uv run … python -m pytest -q tests`), `python3 scripts/smoke_v11_2.py`, `sh scripts/validate.sh`, `git diff --check`;
   - підняти `apps/api/app/version.py`, пін у `scripts/smoke_v11_2.py` і додати запис у `CHANGELOG.md`;
   - якщо змінились промпти, підняти ще й `BASE_STYLE_VERSION`.

   Зміна лише документації версію не піднімає.
5. **Оформлення:**
   - коміт `тип(область): опис` українською (типи для бота звітів: `docs/changelog-reports.md`);
   - заголовок і опис PR українською, з розділами «що змінено» і «перевірка»;
   - без підписів Claude: `Co-Authored-By`, `Generated with Claude Code`.
6. Відкрити PR (`gh pr create --base main`). Після злиття розгортати на TrueNAS з `IMAGE_TAG`, що дорівнює новій версії.
