# Отчёты об изменениях в Telegram

Ежедневный, месячный и квартальный отчёт о том, что изменилось в ARTLINE Rich Studio, приходит в Telegram-чат. Бот такой же, как в Badhairkiller и ukrainerobotics-commerce, плюс квартальные отчёты.

Отчёт собирает `scripts/changelog.mjs`: читает `git log`, раскладывает коммиты по префиксу и отправляет одним сообщением. Зависимостей нет, нужны только `git` и `node` 18+.

Тексты отчёта и команды бота — на украинском, как в оригинале.

## Как писать коммиты

Отчёт собирается из заголовков коммитов, поэтому заголовок начинается с типа:

```
feat(master): eyebrow у кожному блоці
fix(mobile): перемикач розділів проєкту на телефоні
change(prompts): бюджет фото в кожному промпті
```

Область в скобках необязательна. В отчёте она становится меткой: `prompts` → `[Промпти]`.

| Тип | Раздел отчёта |
|---|---|
| `feat` | 🔥 Додано |
| `change`, `refactor`, `perf`, `style`, `ui` | 🔄 Змінено |
| `fix`, `revert` | 🛠 Виправлено |
| `docs`, `test`, `chore`, `build`, `ci`, `deps` | в отчёт не попадает |
| без префикса | Інше |

Заголовок можно писать на украинском и с маленькой буквы. Бот сам сделает первую букву большой и уберёт точку в конце. Коммит на английском попадёт в отчёт как есть. Старые коммиты без префикса не теряются, а идут в «Інше».

Области с человеческими названиями (полный список — `SCOPES` в скрипте):

| Область | В отчёте | Область | В отчёте |
|---|---|---|---|
| `master` | ARTLINE Master | `styles` | Стилі |
| `showcase` | ARTLINE Showcase | `prompts` | Промпти |
| `seo`, `geo` | SEO / GEO | `facts` | Факти |
| `critics` | Перевірки | `review` | Перевірка |
| `landing` | Лендінги | `promo` | Промо-сторінки |
| `infographic` | Інфографіка | `palette` | Кольори |
| `images`, `media` | Зображення, Медіа | `video`, `faq` | Відео, FAQ |
| `web`, `ui` | Інтерфейс студії | `mobile` | Телефон |
| `api`, `deploy` | Сервер | `worker` | Генерація |
| `projects` | Проєкти | `csv`, `export` | Імпорт CSV, Експорт |
| `text`, `i18n` | Тексти, Переклади | `security` | Безпека |

Незнакомая область остаётся как написана.

## Когда приходит отчёт

- **Ежедневный.** Приходит после 5:00 по Киеву, если в этот день его ещё не отправляли.
  - Если сервер в 5:00 был выключен, отчёт придёт первым же запуском после включения.
  - Если изменений нет, ежедневный отчёт молчит.
- **Месячный.** Приходит 1-го числа после 5:00, итоги прошлого месяца. Приходит всегда, даже пустой: молчание 1-го числа не отличить от сломанного бота.
- **Квартальный.** Приходит 1 января, 1 апреля, 1 июля и 1 октября после 5:00, итоги прошлого квартала.
  - Кроме обычных разделов в нём строка по месяцам («Липень: 12 · Серпень: 30 · Вересень: 18») и общий итог.
  - Приходит всегда, даже пустой.
  - Если сервер 1-го числа не работал, придёт первым запуском после.

Граница ежедневного отчёта — последний отправленный коммит, а не сутки. Поэтому ни один коммит не теряется и не приходит дважды. Месячный и квартальный считаются по датам, поэтому повторный запуск даёт тот же итог. Состояние сохраняется только после успешной отправки.

Отчёт строится из истории папки на сервере, а не из GitHub. Пока на NAS не сделан `git pull`, новых коммитов для бота не существует.

> **Первый запуск.** Ежедневный отчёт возьмёт последние сутки, а не всю историю. Месячный и квартальный сразу пришлют итоги прошлого месяца и прошлого квартала: дальше они идут по расписанию.

## Команды в чате

| Команда | Что присылает |
|---|---|
| `/zvit` | изменения за сегодня |
| `/zvit вчора` | за вчера |
| `/zvit 2026-10-03` | за указанный день |
| `/misyats` | с начала текущего месяца |
| `/kvartal` | с начала текущего квартала |
| `/kvartal минулий` | за прошлый квартал целиком |
| `/kvartal 2026-Q3` | за указанный квартал |
| `/stan` | последний коммит, который видит сервер, и когда уходили отчёты |
| `/dovidka` | список команд |

Бот отвечает только в чат из `CHANGELOG_CHAT_ID`. Команды, адресованные другому боту (`/zvit@other_bot`), он пропускает.

Чтобы команды подсказывались при наборе: @BotFather → `/setcommands`, выберите бота и вставьте:

```
zvit - що зробили сьогодні
misyats - з початку місяця
kvartal - з початку кварталу
stan - що бот бачить і коли слав звіт
dovidka - перелік команд
```

## Настройка на NAS

### 1. Бот и чат

1. В @BotFather: `/newbot`. Скопируйте токен. Можно взять и бота алертов студии (`TELEGRAM_BOT_TOKEN`), но отдельный удобнее: отчёты не смешиваются с тревогами.
2. Добавьте бота в нужную группу (или в канал администратором).
3. Узнайте id чата:
   - отправьте в группу любое сообщение;
   - откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates`;
   - найдите `"chat":{"id":-100…}`.

   Для публичного канала можно указать `@имя_канала`.

Если служба уже запущена, `getUpdates` в браузере будет пустым: бот сам забирает очередь. Тогда id видно в журнале службы: после сообщения боту там появится строка `Чат <id>: …`.

Ошибка `USER_BOT_TO_BOT_DISABLED` значит, что в `CHANGELOG_CHAT_ID` стоит id бота. Число перед `:` в токене — это id самого бота, а не чата. Нужен id человека (положительное число) или группы (`-100…`).

### 2. Файл настроек

```bash
cd /mnt/Data/Apps/rich-studio/rich-ai && cp .env.changelog.example .env.changelog && nano .env.changelog
```

Заполните `CHANGELOG_BOT_TOKEN` и `CHANGELOG_CHAT_ID`. Токен лежит отдельно от `.env` и в контейнеры студии не попадает.

### 3. Запуск

```bash
cd /mnt/Data/Apps/rich-studio/rich-ai && docker compose -f docker-compose.yml -f docker-compose.registry.yml --profile changelog up -d changelog
```

```bash
docker compose -f docker-compose.yml -f docker-compose.registry.yml logs -f changelog
```

В логе каждую минуту видно, что решил бот: «Не час: ще рано», «Змін немає», «Надіслано повідомлень: 1».

Проверить без отправки (состояние не меняется):

```bash
docker compose -f docker-compose.yml -f docker-compose.registry.yml run --rm -e CHANGELOG_DRY_RUN=1 changelog node scripts/changelog.mjs --quarter=2026-Q3 --force
```

### Обновление

Когда служба включена, обновляйте с профилем, иначе compose её не перезапустит:

```bash
cd /mnt/Data/Apps/rich-studio/rich-ai && git pull --ff-only && export IMAGE_TAG=<версия> && docker compose -f docker-compose.yml -f docker-compose.registry.yml --profile changelog pull && docker compose -f docker-compose.yml -f docker-compose.registry.yml --profile changelog up -d
```

## Запуск вручную

На машине, где есть node:

```
node scripts/changelog.mjs                                   ежедневный отчёт
node scripts/changelog.mjs --month                           за прошлый месяц
node scripts/changelog.mjs --month=2026-10 --force           за указанный месяц
node scripts/changelog.mjs --quarter                         за прошлый квартал
node scripts/changelog.mjs --quarter=2026-Q3 --force         за указанный квартал
node scripts/changelog.mjs --answer                          ответить на команды
CHANGELOG_DRY_RUN=1 node scripts/changelog.mjs --force       напечатать, не отправлять
```

Тесты: `node --test tests/changelog.test.mjs` (их же запускает CI).

## Переменные

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `CHANGELOG_BOT_TOKEN` | — | токен бота |
| `CHANGELOG_CHAT_ID` | — | куда слать отчёты и откуда принимать команды |
| `CHANGELOG_TITLE` | `ARTLINE Rich Studio` | заголовок отчёта |
| `CHANGELOG_TZ` | `Europe/Kyiv` | часовой пояс расписания |
| `CHANGELOG_HOUR` | `5` | с какого часа можно слать отчёт |
| `CHANGELOG_SEND_EMPTY` | — | `1` — слать ежедневный отчёт и без изменений |
| `CHANGELOG_DRY_RUN` | — | `1` — печатать вместо отправки |
| `CHANGELOG_STATE` | `.changelog-state` | файл состояния; в docker — том `changelog_state` |
| `CHANGELOG_POLL` | `45` | сколько секунд ждать команду |

## Почему так

- **Служба в compose, а не cron.** Задачу cron в TrueNAS надо заводить руками в WebUI. Пока её нет, бот молчит, а снаружи всё выглядит исправным. Расписание должно приезжать вместе с кодом.
- **Образ `node:22`, а не образ студии.** Внутри нужны node, git и папка `.git`, а образы студии собираются из кода без истории.
- **Репозиторий смонтирован только для чтения.** Состояние лежит в отдельном томе и переживает и перезапуск, и `git pull`.
- **Разметка экранируется, длинный отчёт режется по разделам.** Иначе Telegram откажет в отправке (лимит 4096 символов, HTML-режим), и отчёт молча не придёт. Квартальный отчёт обычно длинный и приходит несколькими сообщениями с пометкой «…продовження».
